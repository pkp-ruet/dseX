## SEO Rules (mandatory for every new page/route/section)

Every new page must include all of the following — no exceptions, no reminders needed:

1. **`metadata` export** — `title`, `description`, `keywords` (Bangladesh/DSE-relevant terms), `alternates: { canonical }`, `openGraph` (title, description, url, type)
2. **JSON-LD structured data** — `Article` + `BreadcrumbList` for content pages; `WebPage` or `Organization` for hub/listing pages. Injected via `<script type="application/ld+json">` in the component.
3. **`sitemap.ts` entry** — add the new route(s) with appropriate `changeFrequency` and `priority`. Dynamic routes (like `/learn/[slug]`) must be expanded from their data source, not hardcoded. Use the `data()` helper for pages whose numbers change with the market (lastModified = latest trading date) and `content()` for hand-written pages (no lastModified — never a fake `new Date()`). Only indexable URLs go in: no `noindex` pages, and stock pages only for codes with a DSEF score.
4. **No streaming on indexable routes** — no `loading.tsx` and no `<Suspense>` around primary content on any page Google should index. With a boundary, Next flushes a 200 shell whose `<main>` is only the skeleton and streams the real content into a `<div hidden>` swapped in by JS; Google's first pass then sees an empty page, and `notFound()` / thrown errors can no longer set a status (every unknown `/stock/X` returned 200). That is what emptied the index in Aug–Sep 2026 (17 `loading.tsx` files shipped 2026-09-06, deleted 2026-09-15). Fetch everything a page needs in parallel and `await` it in the page; a slow backend means a slow response, not an empty one. Streaming is fine on `noindex` routes (portfolio, watchlist, register). **A page's primary fetch throws instead of rendering a fallback** (2026-10-28): a page that caught the error and rendered `ErrorState` returned a 200 that ISR cached as the page until the next purge (/dsestockranking, /stocks, /dividend-calendar … after a cold backend); a throw keeps the last good page. Only secondary data keeps `.catch(() => null)` (the homepage blocks too, by design). `generateMetadata` returns `noindex` only on `ApiNotFoundError` and rethrows anything else. A backend outage during `next build` now fails the build instead of shipping error pages.
5. **Titles**: the root layout template already appends `| TopStockBD` — never put the brand in a child page's `title` (23 pages shipped as "… | TopStockBD | TopStockBD"). The one exception is `app/page.tsx` itself: the template does not apply to the root segment, so the homepage title carries the brand explicitly.
6. **Bengali pages**: the `<head>` boot script (`lib/lang.ts`) sets `<html lang>` from the reader's choice (`HtmlLang.tsx` was deleted 2026-10-27); Bengali article bodies keep `lang="bn"` on their own wrapper; `/learn/[slug]` ↔ `/blog/[slug]` topic pairs emit `hreflang` alternates from `lib/i18n-pairs.ts` — add the pair there when writing a guide in both languages.

Pattern for content pages (articles, guides):
- OG type: `"article"`
- JSON-LD types: `Article` + `BreadcrumbList`

Pattern for listing/hub pages:
- OG type: `"website"`
- JSON-LD type: `BreadcrumbList` (if nested) or omit if top-level

This applies to: new app routes, new dynamic route segments, new standalone sections.

## Architecture

DSE (Dhaka Stock Exchange) stock data pipeline with four components:

1. **Scrapers (`scrapers/` + `main.py`)** — CLI entrypoint orchestrating six scrapers in sequence. All scrapers inherit from `scrapers/base_scraper.py:BaseScraper` (HTTP retries, rate limiting via `REQUEST_DELAY`, user-agent rotation).

2. **FastAPI Backend (`backend/`)** — REST API serving the frontend. Cached query layer over MongoDB. Exposes a JWT-authenticated user surface (`/api/auth/*`, `/api/user/*`, `/api/admin/*`).

3. **Next.js Frontend (`frontend/`)** — Production web app. ISR caching, server components for data fetching, client components for auth-gated views (portfolio, profile, admin).

4. **Scoring (`backend/services/scoring_service.py`)** — DSEF 5-pillar score (0–100): Earnings Quality (30%), Financial Health (20%), Operational Efficiency / Moat (20%), Valuation (15%), Dividend Sustainability (15%). Sector classes via `utils/sector.py:normalize_sector` (BANK / NBFI — incl. DSE's "Financial Institutions" — / INSURANCE / GENERAL): banks+NBFIs are scored on a **capital cushion** (equity / total assets, `p2_capital`, `_a2_capital_score`) instead of D/E and skip interest cover entirely (a lender's interest is its cost of goods — the scraper's `total_debt` is borrowings only, so borrowings/equity sat at ~1.0 for every bank and the old "bank D/E anchors" gave all of them a free 10); NIM margin (continuous `_a2_nim_score`, calibrated to the scraped distribution); CFO-positivity fallback. Banks+insurers skip cash/assets; insurers fall back to net margin when no gross-profit line. Sector medians for valuation exclude the company being scored. All growth / trend computations are year-aware.
   - **Growth trajectory (`_trajectory_score`, used for EPS and DPS)**: Theil–Sen slope of ln(value) vs fiscal year (median of pairwise log-slopes — robust to one freak year in five, no span bias), mapped through `_EPS_GROWTH_ANCHORS` / `_DPS_GROWTH_ANCHORS`. A shrinking series scores **below** the 0% mark (the pre-2026-09 gate sent every decline to "neutral", so 10→6 scored the same as flat). Positive growth earns credit only when the current level is held above where the series started (kills fall-and-recover round-trips). 2- and 3-point histories are damped toward neutral. Latest value ≤0 → 0; started ≤0 and profitable now → 5.0. `_earnings_stability` is **peak-to-trough** drawdown (running peak), scaling EPS growth by `0.4 + 0.6·stability` and feeding the P4 `vol_damp`.
   - **Interim results (2026-10, `backend/services/interim_service.py`)**: the latest "Q1/Q2/Q3 Financials" post in `company_news` is parsed (DSE's fixed template: YTD + quarter EPS this year vs last, NOCFPS, NAV per share; figures in parentheses are negative). When it is newer than the audited year: **P/E is on TTM EPS** (`FY EPS − last year's YTD + this year's YTD`, `eps_basis="ttm"`; the row's `eps` is that figure, `fy_eps` the audited one), **P/B on the interim NAV** (`nav_ps`), sector medians use the same effective EPS/NAV, the signal's earnings-drop guard reads `interim_eps_yoy_pct` first, and a negative YTD NOCFPS caps `p2_cfo` at 3 for industrials (not lenders / insurers). Skipped in backtests (`fin_max_year`). All `interim_*` fields ride on the score row.
   - **Debt load (`scoring_service.debt_load`)**: DSE company-page `total_loan_mn` vs `reserve_surplus_mn` and market cap → `debt_level` `over_mcap` / `over_reserve` / `ok` (None for banks, NBFIs, insurers). `over_reserve` caps P2 at 6.9, `over_mcap` at 3.9 and blocks a Buy (`heavy_debt`). Amarstock's borrowings line misses short-term loans (ACMELAB 7.1bn vs DSE 24.8bn).
   - **Valuation (P4)**: own-history P/E and P/B are the **median** of the years present (`own_avg_pe_years` says how many; the page says "since listing" for a listing inside the window). P/E uses the **latest** EPS whatever its sign — a loss-maker has no P/E and its `p4_pe` is 0 (it used to borrow an older positive EPS and look "cheap"; 68 companies). Same rule for the sector-median P/E and P/B inputs. Own-history P/E comes from DSE's audited-table `pe_ratio_basic` (year-end based, verified 2026-09); year-end P/B is rebuilt as `pe_ratio_basic × eps_basic / nav`.
   - **Financial Health (P2)**: interest cover uses the **magnitude** of `interest_expense` (Amarstock books expenses negative for many issuers — ACI's −8.65bn used to read as "no interest" and score 10 on 1.2× real cover). It is `None` (renormalize) when the interest line is missing while borrowings exist or are unknown, and when interest is under 0.5% of borrowings (a stray sub-item, not the real line) — never "debt-free" (that fallback handed 88 companies a 10, one with borrowings at 73× equity). Debt-free (10 / 0 on EBIT sign) only on a zero interest line with no borrowings, or a zero-borrowings balance sheet. Insurers: absent D/E + interest lines are not-applicable (4 of 59 report borrowings, none report interest), weights rescaled to what is present so the 0.60 floor doesn't punish them.
   - **Moat (P3)**: `p3_sector_rank` is a continuous revenue-size percentile within the DSE sector mapped onto 2..10 (was a 4-step ladder that gave the whole bottom half 2.0); companies whose latest revenue is 3+ years older than the sector's freshest are left out (None), solo companies and DSE's "Miscellaneous" sector get the neutral 5.0. `p3_rev_vol` uses annualized year-over-year rates; a shrinking business is scored on how fast it shrinks (max 3.0) and a growing one on how bumpy the growth is, with bands wide enough for a 9–10% inflation economy.
   - **Dividend (P5)**: consistency 0.35 · **payout affordability 0.30** (`p5_payout`: median cash-DPS/EPS over the last 3 paying years, `payout_pct` exposed; a dividend on a loss year → 0) · yield 0.20 · growth 0.15 (growth used to be 0.50 while 67% of companies sat on its neutral constant). A blank audited-table dividend cell is filled from the `dividend_declarations` ledger for that fiscal year (`period_end.year`, interim + final summed) before being read as "no dividend".
   - **ROE**: EPS ÷ NAV per share from DSE's audited table (P1 `p1_roe` and the peer-table `roe_pct`); Amarstock net_profit / equity only when the table has neither (bank lines there don't match DSE's — EBL read 28% instead of 17%).
   - **Stock-page wording (`backend/services/stock_facts.py`)**: Good signs / Watch-outs (`signal_flags.items`, bilingual), the ownership read (govt ≥ 50% = controlling owner; "insiders buying" only on a sponsor rise; a sponsor move > 5 pp is flagged for checking), Health Check overrides, governance watch-outs from a year of news (qualified opinion, BSEC directive/rejection, board/AGM postponed), and the ONE valuation verdict (`valuation_verdict`, P4 bands = the signal's). The fair-value badge uses that verdict; `estimates_disagree` hides the centre figure when the estimate points elsewhere. Fair value is a weighted **median** with peer P/E capped at 1.5× own history.
   - **Corporate actions (`db_service.load_corporate_actions` / `adjust_price_rows`)**: prices on or before a record date are put on today's footing, `(P − cash/share) ÷ (1 + bonus%)`, for the 52-week range (`load_52w_ranges`, the stock page), the chart (`/prices`, rows carry `adjusted`) and the 7-day momentum (`corporate_action` on the momentum snapshot).
   - **Missing-data policy**: a sub-metric whose *inputs* were never scraped is `None` and its weight renormalizes across present metrics with a 0.60 floor (`_weighted_pillar`, max boost 1.67×); present-but-bad data still scores 0. Not-applicable metrics (cash/assets for banks+insurers, D/E + interest cover for banks/NBFIs) are excluded from the pillar entirely, so they neither penalize nor count toward coverage. EPS (P1 m1/m2) and the whole dividend pillar stay 0-filled — absence there is the signal. Per-pillar `pN_coverage` + row-level `data_completeness` are exposed.

### Official close (which price the app shows)

DSE publishes two prices per stock per day and `stock_prices` stores both:

- **`ltp`** — the last executed trade of the session.
- **`close_price`** — DSE's CLOSEP, the **official close**: the weighted average of trades in the final 30 minutes (or the LTP when nothing traded in that window).

**CLOSEP is the one the app prices everything off.** It is DSE's official number — DSE carries it forward as the next day's `ycp` and bases the ±10% circuit limit on it (verified: `ycp` matches the prior day's `close_price` for 100% of stocks, vs ~88% for `ltp`). The two differ for ~14% of stocks on a normal day (median gap ~1%, worst observed 5.3%), widest in thin small caps where one final tick is least representative. DSE closes at 2:30 PM. The after-close jobs (price alerts, portfolio signal flips, the push digest, `portfolio-daily`) wait for the official close: `main.py:_close_is_final` (≥ 200 traded stocks today, ≥ 90% of them with a CLOSEP; `--force` skips it). quick-scrape runs them first and `daily-scrape.yml` runs them again after scrape-all's post-close price scrape; all four are idempotent per Dhaka day, so whichever run first sees final closes sends. Before 2026-10-28 they ran on the 2 PM quick-scrape's last-trade prices.

**Intraday, DSE shows CLOSEP as 0.00** until the session closes. `stock_price.py` stores that as `close_price: None` ("no close yet") and derives `change`/`change_pct` from the LTP instead; the post-close scrape overwrites the row with the real CLOSEP. Never store a 0 close — a 0 made `change = -ycp` (−100% for every stock, and `−৳Infinity (NaN%)` in the portfolio hero; shipped 2026-08-20, fixed 2026-08-30).

Every read path funnels raw `stock_prices` docs through **`db_service.use_official_close(doc)`**, which overwrites `ltp` with the close and re-derives `change`/`change_pct` from `close_price - ycp`. It is idempotent and no-ops when `close_price` is absent (then LTP is the best price available). **The `ltp` key name is deliberately kept** so no router, response model, or frontend component has to change — `ltp` in an API response means the official close. Inside aggregation pipelines (`$max`/`$min`/`$first` for 52-week ranges) use the **`db_service.CLOSE_EXPR`** constant instead.

When adding a code path that reads `stock_prices` directly, apply one of those two — do not read `ltp` raw. Normalized paths: `load_latest_prices`, `load_price_history` (→ `compute_52w_range`), `load_market_movers`, `load_market_index` breadth counts, `compute_market_intelligence`, `top20_service._market_window_raw`, `market_state_service`, `daily_tips_service`, `daily_pick_service`, `db_service.load_52w_ranges` (the ONE shared 365-day hi/lo map — near-extremes, `/api/market/52w`, stock lists, market state and daily tips all read it; don't add another copy of that aggregation), and `scripts/signal_backtest.py`. `load_latest_prices` groups only the last 30 days and fills long-suspended codes one indexed lookup each — never go back to grouping the whole collection.

⚠️ **`stock_prices.date` AND `dse_market_summary.date` are ISO strings** (`"YYYY-MM-DD"`, stamped by `utils/market_hours.py:bst_today_iso`), not BSON dates. Range filters must compare against a **string** bound (`.strftime("%Y-%m-%d")`) — BSON sorts String before Date, so a `datetime` bound silently matches **zero** documents. Four 52-week pipelines shipped with this bug and returned empty for months (fixed 2026-08-20); `market_state_service._index_history` shipped with it too, so `/market-analysis` never knew where the index sat this year and could never say "Going down" (fixed 2026-09-12). `market_snapshots.date` is a string as well.

**Shared UI rules (2026-09-06 consistency pass — keep them):**
- **Buttons by role**: `components/ui/Button.tsx` is THE button — variants `primary | quiet | link | danger | tab`, sizes `sm` 36px / `md` 40px / `lg` 48px, `block`, `iconOnly` (square, the type requires an `aria-label`), `active` (toggled quiet / selected tab). It emits `.btn-primary` / `.btn-quiet` / `.btn-link` / `.btn-danger` / `.btn-tab` (+ `.btn-sm`, `.btn-lg`, `.btn-block`, `.btn-icon`; rules in `globals.css` + `app/styles/states.css`). The old `.ed-btn*`, `.atp-btn*`, `.tx-btn*`, `.add-*-btn`, `.wl-alert-btn` systems are gone (2026-09-22). Never reuse `navbar-link` / `navbar-signup-btn` for page actions — those are navbar-only (2026-10-28: the desktop navbar row is one control language — every item a 40px ghost `.navbar-link`, 12px radius, 16px `ui/icons`, fill on hover / `aria-current`; the language switch is a hairline-framed segmented control with the same fill on the chosen language; Sign up the one clay button; styles in `app/styles/nav.css` → "Navbar row").
- **Plain CSS in `globals.css` beats Tailwind utilities.** The file is ordinary CSS written after `@tailwind utilities`, so a component class that sets `padding` / `width` / `display` silently overrides `pr-10`, `w-auto`, `sm:hidden` on the same element (the password eye icon sat over the text; the mobile `.pf-fab` showed on desktop — both fixed 2026-09-14). `.input-field` now lives in `@layer components` for that reason; put any new "component" class that will be combined with per-use utilities in that layer too, or don't set the same property.
- **Fixed chrome offsets (2026-09-14 overlap audit):** the mobile bottom bar is 60px + `env(safe-area-inset-bottom)`, z-40. The Footer carries the page's bottom clearance (`main` no longer does). Bottom-anchored prompt cards (push opt-in, install, feedback) all use `.above-bottom-bar` + `z-[45]` and mark themselves `data-bottom-card` so only one shows at a time; `.app-toast` sits higher (130px) so it never lands on `.disha-fab`. **Request limits (2026-10-28, `backend/services/rate_limit.py`, tests `backend/tests/test_rate_limit.py`)** — so a script can't take the single 512 MB worker down. `RateLimitMiddleware` (pure ASGI, registered **before** `CORSMiddleware` so CORS stays outermost and a 429 / 413 keeps its CORS headers) does two things: (1) request bodies over `MAX_BODY_BYTES` (64 KB) get a 413, and a chunked body past it is cut off mid-read; (2) token buckets — every request counts against the reader's account when the Bearer token is valid (`GLOBAL_USER` 240/min) or their address (`GLOBAL_ANON` 300/min), plus one ceiling per address (`IP_CEILING` 1200/min). Per-address numbers are generous on purpose: carrier NAT puts many readers behind one address here. Tighter `RULES` on what a script would hammer: sign in 20/min, sign up 30/hour, Google 30/min (per address), screener run 30/min, recommendations 20/min, glance / news-multi 30/min, prices 60/min, stock visits 60/min, feedback 10/hour, push test 6/hour, push subscribe 20/hour, payments 10/hour. The login route also stops an account after 10 wrong passwords in 15 minutes (`LOGIN_FAILURES`, 429 with Retry-After), and `/api/stock-visit` counts one visit per address per stock per 6 hours (`STOCK_VISITS_SEEN` — the counts feed the public popular list). **Not limited**: CORS preflights, `/health`, and requests carrying `REVALIDATE_SECRET` as `x-internal-key` (every server-side `apiFetch` in `lib/api.ts` — an ISR rebuild after a purge comes from a few Vercel addresses) or `x-revalidate-secret` (scrape hooks). The reader's address is `CF-Connecting-IP` / `True-Client-IP` (Render sits behind Cloudflare), else X-Forwarded-For's first entry. In-memory, per worker; each limiter is a bounded LRU. Input caps beside it: string `max_length`s on every user-facing body, finite bounded prices (`allow_inf_nan=False` — a stored NaN made that reader's portfolio 500), and `entitlements.HARD_LIMITS` for every account, Premium included (watchlist 200, armed alerts 50, holdings 300 per portfolio). Push subscriptions must point at a browser push service (`push_service.is_push_service`: FCM, Mozilla, Windows, Apple), at most 10 devices per account, and an endpoint already on another account moves only with the same keys; the sender drops any older non-push-service endpoint.

**Auth dependency chain:** `routers/auth.py` exports `get_current_user` (Bearer → JWT decode → `users` lookup) and `get_current_admin_user` (additional `ADMIN_EMAILS` check). All `/api/user/*`, `/api/admin/*` endpoints depend on these. **Admin = `entitlements.is_admin`** (2026-10-28, the one rule for admin routes, scores refresh, `/me` `is_admin` and admin Premium): the email is in `ADMIN_EMAILS` **and** it is verified (`email_verified`, set by Google sign-in) or the account was created before `ADMIN_UNVERIFIED_BEFORE` — register never verifies an email, so anyone could register an unclaimed admin address. **Tokens**: `decode_access_claims` accepts only login tokens (have `exp`, no `purpose`, `typ` absent or `access`) — the email unsubscribe / open-pixel tokens (`email_service.sign_email_token`, same key, no expiry) were accepted as logins until 2026-10-28; `token_revoked` rejects tokens issued before `users.tokens_valid_after`. `verify_password` returns False for a missing / malformed hash (a Google-only account's password login was a 500); `/login` answers such an account with a 401 that says to use Google.

**Google sign-in:** `POST /api/auth/google` accepts `{id_token}` from `@react-oauth/google`'s `<GoogleLogin>` button, verifies it server-side with `google.oauth2.id_token.verify_oauth2_token` (validates `aud=GOOGLE_CLIENT_ID`, `iss`, `exp`, signature), then resolves the user via `auth_service.create_or_link_google_user`:
- Match by `google_id` → return existing user.
- Else match by email → link (sets `google_id`, `oauth_provider="google"`, `email_verified=true`). The existing `password_hash` is kept **only when the email was already verified**; an unverified one is removed and `tokens_valid_after` set (2026-10-28) — whoever set that password never proved they own the address (someone can register a stranger's email and wait), so the owner signs in with Google from then on.
- Else create a new user with no `password_hash` (Google email is treated as verified).
- Conflict (email already linked to a different `google_id`) → 409.

Returns the same `{access_token, token_type, user}` envelope as `/login`, so frontend `useAuth().login(token, user)` works unchanged. **All successful logins (Google or password) redirect to `/`.** The `users` collection has new optional fields: `google_id` (sparse-unique index), `oauth_provider`, `email_verified`, `picture_url`. Phone-only users (no email) cannot be merged with a Google account by email match — a separate Google-only account will be created; merging those is out of scope.

### Portfolio history (2026-10-24)

- **Holdings stay the source of truth** (`users.portfolio`, unchanged shape — every downstream reader keeps working). Beside it, an append-only **log** (`users.portfolio_log`, capped at 2000): `buy`, `sell` (with `avg_cost`, so profit = qty × (price − avg)), `bonus`, `dividend`. Rules are pure in `backend/services/portfolio_ledger.py` (tests: `backend/tests/test_portfolio_ledger.py`); storage in `portfolio_store.py`; frontend maths in `lib/portfolio-ledger.ts` (`moneyMade`, `yearStatement`, `statementCsv`). - **Bonus shares + cash dividends are applied to the holding** from `db_service.load_corporate_actions` when the record date is after the holding's `added_at`: bonus → `qty × (1 + pct)` floored, same total cost (average falls); cash → a `dividend` row with `qty × cash_ps`.
